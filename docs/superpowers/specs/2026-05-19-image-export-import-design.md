# 图片导出/导入功能设计文档

## 概述

为「日程打卡」应用增加完整的数据导出/导入能力，支持将 IndexedDB 中的图片一并导出为 ZIP 包，导入时自动还原。支持按时间范围筛选导出，保持对旧格式 JSON 导入的向后兼容。

## 架构设计

### 导出数据流

```
用户点击「导出数据」→ 弹出导出对话框
    ↓
选择时间范围（默认全部）
    ↓
创建 JSZip 实例
    ↓
按时间范围筛选 days，收集被引用的图片 ID
始终包含模板图片
    ↓
构建 data.json（version 2，图片引用为文件名）
    ↓
遍历图片 ID，从 IndexedDB 读取 Blob，添加到 ZIP 的 images/
    ↓
生成 ZIP 文件并触发下载
```

### 导入数据流

```
用户选择文件（.zip 或 .json）
    ↓
判断文件扩展名
    ↓
ZIP 流程：JSZip 解压 → 读取 data.json → 图片写入 IndexedDB → 覆盖 state → 刷新
JSON 流程：现有逻辑（图片需重新上传）
```

## 导出对话框

在现有「导出数据」按钮位置，点击后弹出 `<dialog>`：

- **时间范围**：两个日期输入框（起始日期、结束日期），默认为空表示全部
- **导出按钮**：生成 ZIP 并下载
- **取消按钮**：关闭对话框

## 导出格式

### ZIP 包结构

```
日程打卡数据-2026-05-19.zip
├── data.json
└── images/
    ├── a1b2c3d4_阅读30分钟.jpg
    ├── e5f6g7h8_查看JIRA看板_2026-05-19.jpg
    └── ...
```

### data.json 格式（version 2）

```json
{
  "app": "daily-checkin",
  "version": 2,
  "exportedAt": "2026-05-19T10:30:00.000Z",
  "hasImages": true,
  "data": {
    "templates": [...],
    "days": { "2026-05-19": { "tasks": [...] } },
    "settings": { ... }
  }
}
```

与旧格式差异：`version` 改为 2，新增 `hasImages` 字段，`images` 数组值改为文件名。

### 图片文件命名

- 模板图片：`{图片ID}_{模板名称}.jpg`
- 每日任务图片：`{图片ID}_{任务名}_{日期}.jpg`
- 特殊字符（`/ \ : * ? " < > |`）替换为 `_`

### 导入时的匹配逻辑

从文件名提取第一个 `_` 前的部分作为图片 ID，与 JSON 中的引用匹配。

## 时间范围筛选

### 筛选规则

- **days**：只包含日期在 `[startDate, endDate]` 范围内的记录
- **templates**：始终全部包含（模板不绑定日期）
- **图片**：只导出被筛选后的数据引用的图片
  - 模板图片始终包含
  - 每日任务图片：只包含被筛选 days 引用的图片

### 默认行为

起始日期和结束日期均为空 = 导出全部数据。

## 导入兼容性

### ZIP 导入（新格式）

1. JSZip 解压
2. 读取 data.json
3. 遍历 images/ 文件夹，从文件名提取 ID
4. 读取文件为 Blob，写入 IndexedDB（相同 ID 覆盖，无副作用）
5. 用新 state 覆盖 localStorage
6. 刷新页面

### JSON 导入（旧格式）

保持现有逻辑不变，图片需重新上传。

### 重复导入

安全：图片用 `imageDB.put`（upsert），相同 ID 覆盖相同数据。State 覆盖式替换，结果等同于无变化。

## 技术依赖

- **JSZip**（~10KB）：ZIP 创建和解压，CDN: `https://cdn.jsdelivr.net/npm/jszip@3/dist/jszip.min.js`
- **idb**（已引入）

## 边界情况

- **无图片**：导出时只有 data.json，没有 images/ 文件夹。走现有 JSON 导出逻辑
- **图片缺失**：导出时某个 ID 在 IndexedDB 中不存在，跳过该图片
- **大文件**：逐个读取图片添加到 ZIP，避免一次性加载所有图片到内存
- **文件名冲突**：UUID 前缀保证不冲突
